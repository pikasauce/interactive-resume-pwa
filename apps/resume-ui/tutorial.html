Use this project as a small, explainable release-engineering portfolio piece. Make one change at a time, verify it, then ship it.

01

Run the system

Two small services, one user-facing artifact

Run npm run dev. The Node server at port 3000 serves the PWA; the Express service at port 3001 supplies a JSON release signal. Open the app and use browser DevTools → Network to see the REST request.

Try: edit the message in services/resume-api/server.js, restart the API, then confirm the new signal appears in the interface.

02

Progressive web app

Deliver an app that still helps when connectivity does not.

manifest.webmanifest supplies install metadata. service-worker.js caches the app shell during installation and answers requests from the cache before the network. In Chrome DevTools → Application, verify the manifest and toggle offline mode after the first load.

Try: add a static asset to APP_SHELL, increment the cache name, and confirm the refreshed cache is installed.

03

Quality as code

Specify the experience in Playwright.

Run npm run test:e2e. The Playwright config starts both services and checks the public résumé and the live release signal. Tests are a release gate, not a manual checklist.

Try: add a test for the print button or for a navigation anchor. Make it fail first, then implement only what makes it pass.

04

CI and release

Make the repeatable path the easy path.

.github/workflows/ci.yml runs syntax and browser checks for pushes and pull requests. scripts/release/release.sh packages the UI, API, and release notes as an inspectable artifact.

Try: run npm run ci:check; then run bash scripts/release/release.sh demo-1. Read the generated notes before treating an artifact as releasable.
